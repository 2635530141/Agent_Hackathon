Connect each user's Google calendar

The private preview includes account-specific Connect, Refresh and Disconnect controls, a primary-calendar read of the next 14 local dates, private event titles and the same editable timetable.

For a developer or host-operator test on Windows, open Start-Calendar.cmd in the repository. Select the team's Web OAuth JSON privately when prompted. The launcher checks the file, callback, port and existing runtime keys, then opens the private login page. The regular demo stays synthetic.

Ordinary users only sign in and consent in Google. A shared deployed host is configured once by the team administrator; users do not need client JSON or an API key.

  1. The team administrator configures the OAuth client privately. Git does not contain the credentials.
  2. While Google is in Testing, the administrator adds each consenting test account. Each person then authorizes their own Google calendar.
  3. Create a private local account first, then choose Connect Google Calendar. Demo accounts and data are separate.

For access_denied / 403, check test-user eligibility and school policy. For redirect_uri_mismatch, the callback must match exactly, including 127.0.0.1 versus localhost and the port. Refresh reads the primary calendar for the next 14 local dates.
