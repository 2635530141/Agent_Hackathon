# 日程模块：验证与检查步骤

工作分支：`shuluun`。基线：团队 `main` 的 `03ef6c4`，包含最新匹配与 Session/邀请实现。

## 本次改动

- 在团队指定的日程文件中实现每周空闲、临时增减、考试与日历忙碌扣除、考前优先窗口、同等时长的替代时段。
- 适配队友按学生 ID 读取日程的三个接口，保留临时 free 记录并移除所有匹配数据中的事件标题。未知 ID 不会返回组织者日程。
- 匹配中的时间读取、空闲计算、备注改期和营业时间比较统一处理时区，复用日程引擎；保留原有评分权重和地点选择逻辑。
- “仍然学习”只忽略组织者自己的日历事件，考试、手动忙碌、周空闲边界及其他人的日历不变。
- Session 页面支持不存在替代时段的情况，并正确显示从带时区链接进入的表单时间。
- 保留独立的日历 API、Google OAuth/加密凭据/确认写入执行器和 Omnara 只读模拟演示，补齐安装、测试和接入文档。

## 你可以这样检查

先看 <http://127.0.0.1:8014/schedule>。服务已启动时直接打开；否则从仓库根目录运行：

```powershell
python -m pip install -r requirements.lock
python -m uvicorn app.main:app --host 127.0.0.1 --port 8014 --no-access-log
```

1. 日程页默认 10 月 29 日 16:00–21:00，应该显示 16:00–18:00、19:00–21:00 两段空闲。
2. 把周四结束时间改为 20:30，保存后第二段应缩短；检查后可以改回 21:00。
3. 添加 10 月 28 日 19:00–20:00 的 Extra free time，再到 Matching 查询同一天同一时段，应能使用该临时空闲。删除后该时段不应继续用于组织者匹配。
4. Session 页请求 10 月 29 日 18:00–21:00，应先看到自己的日历冲突和经过检查的替代时段。
5. 给某个空闲时段添加考试，再请求同一时段，考试应阻断学习；Study anyway 不能跳过考试。
6. 点击 Google 设置检查不会把未配置账号显示成已连接。

代码重点看 `app/schedule_core.py`、`app/matching_core.py` 的时间适配、两个 router、日程与冲突模板，以及 `tests/test_schedule_matching_integration.py`。共享 contracts 和队友的 Store/评分权重未修改。
